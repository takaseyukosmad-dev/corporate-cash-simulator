# 法人資金形成シミュレーター 追加開発要件定義
作成根拠：2026年10月23日打合せ（19:57〜1:01:12）および「スーパー福利厚生完全版」

## 0. 開発の進め方（重要）
- デスクトップに新しい開発フォルダを用意する。既存「役員報酬・退職金 比較シミュレーター」の原本は編集・削除しない。
- 既存アプリのコードを読み取ってデザインと既存計算ロジックを再利用し、別の作業コピー（または新しいプロジェクト）で開発する。
- 最終的には「役員報酬・退職金 比較」と「法人資金形成比較」の２つをタブ等で切り替える統合アプリを目指す。既存タブの回帰テストを必須とする。
- 実装前に既存構成・技術スタック・入力/計算ロジック・データ構造を調査し、変更計画と未確定事項を短く報告する。
- まずブラウザで動くローカル版を完成させる。認証・共有・公開は別フェーズ。

## 1. 比較の目的
### A. 既存タブ（変更しない）
役員報酬を受け取る場合と、退職金原資として準備し退職金として受け取る場合の個人手取り比較。既存の挙動と見た目は保全。
### B. 新規タブ「法人資金形成比較」（仮称）
法人の年間利益から、「何も対策しない」場合と、「企業型DC・福利厚生保険・役員保険・任意の役員報酬減額を組み合わせた」場合を比較し、法人の現金、法人保有保険の解約返戻金、DC加入者の資産をそれぞれ可視化する。退職金支給後の個人税額は計算しない。DC資産を法人保有現金と誤認させず、資産帰属を明記した参考合計のみ任意表示。

## 2. 入力項目
### 共通・基本
- 年間法人利益（万円）：現行役員報酬を支払った後、追加施策前の利益であることを入力欄に明示
- 比較期間（年）：例 5/10/15/20/25/30、または整数入力
- 法人実効税率（%）：編集可能。概算税率として表示。税率階層・繰越欠損・各種税額控除等は別途詳細モードがない限り対象外
- 対象地域（既存の税・社会保険計算が使える場合のみ。新規法人税率を都道府県だけで厳密自動決定しない）
- 毎年利益一定の仮定をUIに明示、将来は年別入力を拡張できるように設計
### 企業型DC
- 加入人数（0以上の整数。役員人数を含め任意）
- 1人あたり月額掛金（円、編集可能）または人数別掛金
- 参考初期値：3,000円～62,000円は打合せ上の想定であり法定適用上限として確定表示しない。適用時期・他制度掛金等を検証するよう注記
- DC運用年率（%）と拠出期間（年）
- 掛金総額と20年後等の運用評価額を区別
- 掛金の損金算入が成立するスキームを前提とする場合は注記し、給与からの振替と会社の追加負担を二重計上しない
### 福利厚生保険・役員保険（各々独立）
- 使用する/しない
- 年間保険料（万円）
- 損金割合（0～100%、数値入力を基本。0/40/50/60/100%などプリセットを用意してもよい）
- 満期まで払い込む通常ケースの満期解約返戻率（%）
- 払済ケース：何年目まで払うか（例 5/10年）、評価する年（通常は比較期間末）、その時点の累計払込保険料に対する解約返戻率（%）
- 返戻率は商品・設計条件により変わるため自動的に『5年で300%』などの保証値は設定しない。ユーザーが保険設計書の値を手入力
- 保険資産の名義・解約返戻金の帰属を明示し、法人契約のみ法人保有資産として表示
- 払済後は保険料の支払を停止。払済後の返戻率は入力された数値から計算し、線形増加や一定複利を勝手に仮定しない
### 役員報酬
- 報酬減額をする/しない（任意）
- 減額する役員の人数、1人あたり月額減額（円）又は年間総減額（万円）
- 既存アプリの役員報酬に関する税・社会保険計算を、適用条件が合う場合に再利用する。ただし新規タブで報酬減額した金額をすべて保険料に移すという強制条件は設けない

## 3. 必須計算・表示
- 比較基準：対策なし時の年次法人税と税引後現金増分
- 対策あり：各年の役員報酬減額による会社支出減、会社負担DC、保険料支出、損金算入額、概算法人税、期末法人現金、保険返戻評価額、DC運用資産
- 初年度・比較期間末および年次推移を表示。比較期間中に払済がある場合は、保険料停止の効果を現金推移に反映
- 対策前/後の「法人税累計」「法人に残る現金」「法人保有保険解約返戻金」「法人保有現金+保険評価額」「DC加入者資産」「参考総額」「差額」を別々に表示
- 比較グラフは「現金」と「法人保有保険」と「DC」を色または凡例で区別し、法人と個人の資産を混同しない
- 税金・保険の損金算入計算は実際の保険商品・契約・法人税務処理に依存する。便宜上の定率概算には『概算』ラベル
- マイナスの税引前利益、足りない現金、現実的でない払込額等については警告。法人税額を単純に負値にはしない
- 退職金支給、受給時課税、将来の保険解約益課税、DC受給時課税などは別の計算層・将来課題とし、未計算である旨を明示

## 4. 計算エンジンの設計上の注意
- 会社利益 P は現行役員報酬を控除済みと仮定。役員報酬減額 R は利益を増加させる。DC追加会社拠出 D を二重計上しない。保険料を H, E、損金率を h,e とすると、単年度の『追加施策後課税対象利益の概算』は P+R-D-hH-eE （ただし報酬振替型DCの場合は給与減額分と掛金増額を相殺して扱う）とし、確定申告上の税額を意味しない。
- 当期の現金増分は支出と税額を別々に計算。損金算入しない保険料分は支出ではあるが税控除できない、という相違を反映。
- 経費計上割合と解約返戻評価の税務処理は契約内容に依存。単純な『保険料×損金率』では不十分な契約があるため個別税務検証を促す。
- DCは加入者帰属の老後資産であり法人資産の現金残高ではない。
- 利益から役員報酬減額・保険費用・DC費用を差し引いた後の法人税額と現金差を年次に追跡する。積立額の二重計上を防ぐ。
- 運用年率は非保証。入金タイミング（月末拠出など）を明記し、一貫した複利計算を使用。
- 業務確認用に計算根拠・式・入力値を展開できる画面を作る。

## 5. UI / 操作要件
- 既存アプリと同一のデザイン体系、フォント、色、余白、入力部品を踏襲
- 上部で2つのモードを切り替え。既存タブはそのまま残す
- 新規タブの入力は「基本条件」「企業型DC」「福利厚生保険」「役員保険」「役員報酬減額」にグループ化
- 通常満期 / 5年払済 / 10年払済 を並べて比較できる。払済年数は任意指定可
- 入力変更時に即座に再計算、概算値の根拠を確認できる
- 画面は説明時の共有を想定し、概要KPI、年次のグラフ、明細テーブルの順に見せる
- デモ用の仮データと全項目リセットを用意
- CSVまたは印刷出力は可能なら追加、MVPで難しい場合は次フェーズ

## 6. 受け入れテスト
1. 追加施策がすべて0なら、対策なしと対策ありの数値が一致する。
2. 役員報酬の減額だけなら、利益・税・現金に反映され、保険料は自動で増えない。
3. 保険損金割合0%と50%では税計算が異なるが、実際の支払保険料は同額。
4. 5年払済設定なら6年目以降の保険料支出は0、比較期間末の返戻率が反映される。
5. DC人数0ならDC項目の金額は0。DC運用利回り0%の場合は掛金総額と運用額が整合する。
6. 既存「役員報酬・退職金 比較」の代表的な入力例が開発前後で一致する。
7. 各年の現金フロー、保険資産、DC個人資産に二重計上がない。
8. 未確定の税制・制度上限や保険返戻率を『保証』と表示しない。

## 7. 進行順序
フェーズ1：既存ソース調査と仕様の照合 → フェーズ2：新規タブとモック画面 → フェーズ3：計算ロジック・テスト → フェーズ4：比較図と説明用表示 → フェーズ5：既存アプリ統合検証。
会員認証、FANTS外部リンク公開、結果保存は別フェーズとして設計のみ残す。

## 8. 会議資料内のモデル例（固定商品値ではない）
- 年間利益3,000万円という現場相談の例
- 法人の預金だけで20年2億円形成する例：法人税を30%として必要な利益を概算
- DC2人、20年、資料記載の原資2,976万円・6%モデル評価5,623万円
- 福利厚生保険20年継続と10年払済を比較する資料例
上記は説明用参考値として用い、実装時には数式との整合性、制度条件、保険設計書での裏付けを検証。資料の印字値を常に出すように逆算補正しない。
